# 你画我看：双设备画板

## 使用入口

小游戏乐园 → 你画我看。

1. 两台 iPhone/iPad 安装包含本功能的应用，保持前台使用。
2. 建议打开 Wi-Fi 和蓝牙，第一次使用允许本地网络访问；同一 Wi-Fi 不需要连接互联网。
3. 一台点「创建画板」，另一台点「加入画板」，选择创建端显示的设备名称。
4. 创建端确认「允许观看」后，加入端自动显示画布。
5. 创建端可以换颜色、调粗细、撤销和清空；加入端只观看。
6. 短线或进入后台后，点击「断开」，重新创建/加入；创建端在本页面保留的完整画布会重新同步。

没有服务器、账号或互联网依赖。实际传输路径由系统选择，不保证只走蓝牙。范围、连接稳定性受设备和无线环境影响。

## 实现约定

- 使用 MultipeerConnectivity，服务类型 `crm-draw`，强制加密并由创建端明确确认邀请，每次只允许一个观看端。
- 协议版本为 1，使用 JSON 与可靠有序消息；创建端是唯一状态源，观看端无法修改其画布。
- 画布比例固定 3:4、坐标归一化，适配不同屏幕时不拉伸。
- 连续点以约 30Hz 分批传输；撤销、清空前先提交未发送点，操作带递增修订号。
- 观看端连接后请求完整快照，修订号不连续时重新请求快照。
- 限制 500 笔和 20000 个点，达到上限提示撤销或清空；拒绝超长、非法或越界数据。
- 进入后台、返回或切换标签时释放连接，重新进入需要重新连接；不提供后台画板服务。
- 画布仅在当前页面内存中保留，退出页面或结束应用不保存。
- 本功能不配置、不激活音频会话。

## 两台真机验收

- 创建后再加入、先加入后创建，均能发现且必须确认邀请；拒绝后能再次申请。
- 同一 Wi-Fi 无互联网环境同步；没有共同热点时验证附近直连能力。
- 连续画线、快速画点、六种颜色、三种粗细，两端一致。
- 长线结束后立即撤销、清空，观看端不出现残留。
- iPhone 与 iPad 对照画圆和方框，画面比例一致。
- 断开后创建端继续画，再重新加入，补齐全量内容。
- 关闭 Wi-Fi、锁屏、切后台、切标签后检查状态，重新连接恢复。
- 第三台加入时不进入已有二人会话。
- 拒绝本地网络权限后，在系统设置开启权限，再重试。
- 测试画布容量上限及清空后继续绘画。
- 原有其他 App 音乐播放时打开画板，验证不触发音频中断。

真机发现、权限弹窗、无线直连和双设备延迟必须由真实设备验证；单机协议测试不能替代。

## 邀请与连接修正（诊断版本 v2）

- 使用页面内设备列表与邀请确认区，不再依赖系统 MCBrowserViewController 弹出/关闭时序。
- 创建端收到邀请后，页面显示「允许观看」「拒绝」，即使已有模态内容也不会静默拒绝。
- 同页重试复用设备身份；无关设备及旧会话的回调不能清除当前连接目标。
- 保持 MCEncryptionRequired；证书回调仅接受已选择或明确允许的目标。此确认不是CA证书身份认证。
- 观看端收到快照后回复 ready，创建端收到确认后才停止广播并标记就绪。
- 分别记录发现、邀请、用户确认、证书回调、握手、快照与就绪；右上角「连接日志」复制最近80条事件及系统版本。
- 邀请确认30秒超时，加入端等待45秒；允许后的握手35秒、连接后画布同步15秒。超时释放旧会话，不自动放行其他设备。
- 不将模态页面引起的 viewDidDisappear 当作断开条件，仍在返回、切标签、进入后台时释放连接。

### 本次问题的验证顺序

1. 两台设备都安装本次版本，确认右上角都有「连接日志」。
2. 首轮让两台连接同一个普通 Wi-Fi，开启本地网络权限；临时关闭 VPN/代理用于排除网络路由影响。
3. iPhone 12 Pro Max / iOS 16.5 创建 → iPhone 16 / iOS 18.5 加入，确认创建端出现页面内邀请，允许后两端显示画布就绪。
4. 交换角色再验证；继续检查画线、撤销、清空和重连。
5. 若失败，在两台设备点击「连接日志」，保留两份文本。发现成功只能证明发现通路可用，不能证明会话握手已成功。
6. 同 Wi-Fi 成功后，再验证无共同热点下的附近直连。

### 连接回归程序

`CRMNearbyDrawingConnectionTests.m` 是独立 iOS 验证程序，和控制器、画布模型一起链接 UIKit、Foundation、MultipeerConnectivity 后在模拟器运行；它不加入主应用的 Sources。
使用网络替身测试真实控制器回调：已有模态内容时保留邀请、重复允许只回复一次、页面消失不误断开、目标证书与非目标拒绝、旧/无关设备回调、快照就绪确认、旧超时不清理新会话。
测试成功会在验证程序沙盒 Documents/connection-test-result.txt 写入结果。测试不验证真实无线握手，仍需上述两台真机验收。

## 转场修正及真机网络诊断（v3）

### 已确认的系统记录

2026-10-21，iPhone 12 Pro Max（iOS 16.5）与 iPhone 16（iOS 18.5）连接同一台其他手机提供的热点。
第二次连接在用户允许后进入 Connecting，未到 Connected。
iPhone 16 的 Multipeer GCKSession 在向另一台局域网地址发送 ICE 探测时，持续返回 `Sendmsg failed with error No route to host (65)`，最终 `ICE timeout expired`。
同一时段系统 nehelper 记录本应用 `Local network allowed by preference`。
因此可以定位为连接通路建立失败；不能据此认定证书错误、两个系统必然不兼容，或确定热点一定启用了隔离。Wi-Fi/热点的设备间互通与其 4G 互联网接入是不同通路。

### 处理

- 不在 viewWillDisappear 开始时立即断开。等待转场完成，确认页面脱离导航栈或被实际关闭后清理；取消的交互转场保留连接。
- 记录页面转场开始标记、取消及确认离开的具体条件。
- 发现列表 lostPeer 日志更正为「从发现列表消失」，不推断对方主动停止广播。
- 连接失败提示改为中性说明，不将所有未连接状态描述成对方拒绝。
- 转场回归、已有邀请/会话回归及源码编译检查通过；不代表已解决真机热点通路。

### 下一步对照

先让两台加入同一个普通路由器 Wi-Fi，避开访客网络和设备隔离模式，再交换角色连接。此验证不需要互联网或服务器，也不需要先升级手机系统。
若普通 Wi-Fi 成功而原热点失败，应继续检查热点的设备间互通；若仍失败，继续对照系统路由/本地网络状态。Apple DTS 曾说明 iOS 18.6 包含重要的本地网络隐私修复，但现有日志不足以确认本例正是该缺陷，不把系统升级作为已证实的解决方案。
参考：https://developer.apple.com/forums/thread/794527

## 补充：12 Pro Max 创建时没有邀请提示的直接证据

进一步展开 iPhone 16 在 2026-10-21 15:52:51 的 Network.framework 连接日志：

- 已发现12 Pro Max的Bonjour服务，并尝试打开邀请用的TCP输入/输出流。
- 在服务解析后，IPv4、IPv6及awdl0上的连接路径均报告 `unsatisfied (Local network prohibited)`。
- 对应时段12 Pro Max没有收到 `didReceiveInvitationFromPeer` 回调。

因此，此次无确认提示发生在邀请送达之前，不能判断为iOS 16缺少邀请界面支持。
稍后另一次会话的nehelper虽记录 `Local network allowed by preference`，但ICE探测仍出现 `No route to host (65)`。两条记录反映的时段及层次不同，不能仅凭设置偏好已允许就排除有效连接路径受限。

优先核对iPhone 16「设置 → 隐私与安全性 → 本地网络」中的本应用开关；若已开启但仍出现禁止记录，可在保留应用数据的前提下重新切换该开关、彻底退出并重新打开应用，再测试。若权限状态仍异常，可重启iPhone 16后对照。以上设置操作由用户明确操作，不由代码绕过或自动修改。
修复权限状态后先在原网络重试，再以普通路由器Wi-Fi区分热点环境影响。现有证据不足以直接断定热点隔离，或断定两个系统版本必然无法互联。
