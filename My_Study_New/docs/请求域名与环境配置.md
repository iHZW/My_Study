# 请求域名与环境配置

## 配置入口

当前没有可用后台，四套 API Base URL 均留空。配置缺失会在发送前通过失败回调和 Lumberjack 明确提示，不会访问旧 Apifox／Postman Mock，也不会拼接成不明服务器地址。

统一填写文件：`My_Study/Configuration/NetworkEnvironments.xcconfig`。

```xcconfig
ZW_URL_SLASH = /
ZW_API_BASE_URL_DEV =
ZW_API_BASE_URL_QA =
ZW_API_BASE_URL_PL =
ZW_API_BASE_URL_ONLINE =
```

有实际后台后，将相应值填写为：

```xcconfig
ZW_API_BASE_URL_DEV = https:$(ZW_URL_SLASH)$(ZW_URL_SLASH)实际开发域名/api/v1
```

这里的“实际开发域名”是填写格式说明，不是需要照抄的配置。xcconfig 中直接书写 `https://` 容易让双斜杠后的内容变成注释，因此使用斜杠变量。

共享域名可直接提交到该配置文件。本机配置可新建同目录的 `NetworkEnvironments.local.xcconfig`，写入相同变量进行覆盖；该文件已加入 `.gitignore`。本机覆盖只用于开发，不应放入正式构建环境。

CI 可以通过同名 Xcode Build Settings 注入，例如 `ZW_API_BASE_URL_ONLINE=实际HTTPS地址`。构建变量进入 Info.plist，不应将 token、密码或私钥放入这些变量。

## 环境选择

| Target | Debug / QA_Dev | QA | Release |
| --- | --- | --- | --- |
| My_Study | dev | qa | online |
| My_Study_Sit | qa | qa | qa |
| My_Study_Uat | pl | pl | pl |

`ZW_NETWORK_ENVIRONMENT` 为默认环境；`ZW_ALLOW_ENVIRONMENT_SWITCH` 控制调试切换。Release 构建禁止手动切换，并忽略历史保存的选择。其他构建还需存在 DEBUG／DOKIT 编译标识才允许使用环境切换界面。

目标选定环境和运行时可切换性是两件事：例如 SIT 的 Release 仍使用 qa，但不能通过调试页改为其他环境。

地址的单一来源是项目级 xcconfig，三个应用 Info.plist 的 `NetworkConfiguration` 在构建时展开变量。已有各 Target 的 CocoaPods／基础 xcconfig 引用保持不变。原 Build Settings 中重复硬编码的 `HTTP_SERVER_HOST` 已移除。

`EnvConfig.plist` 继续提供各环境的 SDK 配置描述，不再重复保存 API 域名，也不再依赖历史 Bundle ID 推断网络环境。

## 请求构建

```text
构建配置选择环境
    → Info.plist.NetworkConfiguration
    → Environment / Config
    → ZWSiteAddressManager
    → ZWEndpointConfiguration 校验和拼接
    → HttpClient / Http2
    → ZWNetworkTransport
```

业务代码使用相对资源路径：

```objc
NSString *path = @"/zq/crm/trade/app/approval/list";
```

如果 Base URL 是 `https://实际域名/api/v1/`，上述路径会保留 `/api/v1` 前缀，不会因为开头的斜杠丢失版本路径。

统一规则：

- 未配置、未展开的构建变量、无效地址：直接失败，不发送请求。
- Base URL 不允许查询串、URL 片段和内嵌账号密码。
- 生产环境只允许 HTTPS；调试且非 online 环境可使用 HTTP 进行局域网联调。
- 相对请求支持查询参数，拒绝协议相对地址和 `..` 路径穿越。
- 显式第三方绝对 URL 可以继续使用，但同样校验协议和账号字段；它们不被强制重写到主 API 域名。
- 登录与首页历史硬编码已改为相对路径。未沿用任何废弃 Mock 地址。

会员系统 `ZWMemberApi` 的服务器配置属于独立服务，保留原入口；图鉴、WebView、第三方 SDK 等独立服务也不会被主 API 配置覆盖。后续如需管理更多服务，应为它们增加明确的服务配置键，避免共用一个主 API 地址。

## 切换环境

调试页列出 dev／qa／pl／online，未配置地址的环境会标注“未配置 API 地址”。保存前校验，空地址不能被保存为下一次启动的环境。

保存成功后下次启动生效，当前进程继续使用当前环境，不热切换正在执行的请求。不会调用 `exit(0)`，也不会删除整个应用数据目录。重启后 SDK 与主 API 从同一环境描述初始化。

键值形式的网络缓存已按环境和 Base URL 区分，不读取此前没有命名空间的旧缓存。业务显式指定的绝对缓存文件路径由对应业务负责隔离；本次没有删除这些文件。

项目历史账号体系没有完整的多环境凭证存储协议。本次不虚构 token 刷新或凭证迁移能力；接入实际鉴权后台时，应将账号、token 和 Cookie 按服务与环境隔离，并验证切换后的登录态。

## 验证

`tests/ZWEndpointConfigurationTests.m` 覆盖空配置、未展开变量、HTTPS 约束、非法基础地址、版本前缀、查询参数、路径穿越和环境标识，共 21 项检查。

在项目目录运行：

```bash
xcrun clang -fobjc-arc -framework Foundation \
  -I "My_Study/Configuration" \
  "tests/ZWEndpointConfigurationTests.m" \
  "My_Study/Configuration/ZWEndpointConfiguration.m" \
  -o "/private/tmp/my-study-endpoint-tests"

"/private/tmp/my-study-endpoint-tests"
```

本次不访问生产服务或真实后台。运行 App 时尚未配置主 API 的相关功能会收到配置错误；本地页面和独立配置的会员服务不依赖该空地址。
